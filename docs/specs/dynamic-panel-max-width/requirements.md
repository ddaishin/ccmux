# requirements — サイドバー/プレビュー幅ドラッグ上限の動的化

## 背景

ファイルツリー幅・プレビュー幅のマウスドラッグリサイズは上限が固定値
（tree: `col.clamp(10, 60)`・preview: `.clamp(15, 80)`）で、広い端末でも
それ以上広げられない。上限を「現在の画面幅 − 他領域が確保すべき最小サイズ」
まで動的に許可する。

## スコープ

- 対象: ファイルツリー幅・プレビュー幅のドラッグリサイズの**最大値**のみ
- 対象外: ペイン分割比クランプ（0.15〜0.85）、縮小時フォールバック、
  保存幅の自動縮小、最小値（tree 10 / preview 15）の変更

## 受け入れ基準（EARS）

1. WHEN ユーザーがファイルツリー境界をドラッグする
   THE SYSTEM SHALL 幅を `10 〜 (画面幅 − 20 − プレビュー描画中ならその幅)` の
   範囲で更新する（旧固定上限 60 を超えて拡大できる）。

2. WHEN ユーザーがプレビュー境界をドラッグする
   THE SYSTEM SHALL 幅を `15 〜 (画面幅 − 20 − ツリー描画中ならその幅)` の
   範囲で更新する（旧固定上限 80 を超えて拡大できる）。

3. WHEN 相手側パネルが非表示（トグルオフまたは狭小フォールバックで非描画）である
   THE SYSTEM SHALL その幅を差し引かず、より広い上限を許可する。

4. WHEN 画面が極端に狭く動的上限が固定最小値を下回る
   THE SYSTEM SHALL 上限を最小値（tree 10 / preview 15）に縮退させ、
   panic せずドラッグを最小幅で受け付ける。

5. WHEN 端末リサイズで幅が入り切らなくなる
   THE SYSTEM SHALL 既存フォールバック（preview → tree の順で非表示）を
   従来どおり適用する（保存幅は変更しない）。

6. WHEN ペイン分割境界をドラッグする
   THE SYSTEM SHALL 従来どおり比率 0.15〜0.85 でクランプする（挙動不変）。

## 非機能

- `cargo test` 全緑・`cargo build` 成功
- rustfmt 非適用（周辺スタイルへ手合わせ）
- レイアウト定数 `MIN_PANE_AREA_WIDTH = 20` の定義は 1 箇所に統合し、
  値・挙動は変えない
