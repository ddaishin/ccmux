# requirements.md — filetree-mtime-sort(ファイルツリーの更新日時降順ソート)

## 1. 背景と目的

ファイルツリーの並びは「ディレクトリ先頭 → 名前昇順(大小無視)」で固定されている(`src/filetree.rs:101-102`)。
Claude Code が直近に編集したファイルを素早く辿れるよう、既定を更新日時(mtime)の降順にし、`s` キーで名前順と切り替えられるようにする。

## 2. 利用者と保守者(条件3)

- 利用者: 本人。ccmux のサイドバーで、作業中のファイルを開くために日常的に使う
- 保守者: 本人。`local/v0.6.2-patched` のローカルパッチとして運用する(upstream には未 PR)

## 3. 成功基準(条件1)

- 起動直後のファイルツリーで、各ディレクトリの中身が「ディレクトリ群 → ファイル群」の順に並び、各群の中は mtime の降順になっている
- ファイルを更新すると、2 秒以内の自動再スキャンで、そのファイルが属する群の先頭へ移る。ただし次の 2 つは除く(§7 の既知の限界): 項目が 500 件を超えるディレクトリで read_dir の順に打ち切られたファイル、Windows で書き込み用に開いたままのファイル
- `s` キーで名前順と更新順を切り替えられ、今のモードがサイドバーの題に表示される
- `cargo test` が緑で、キーヒントの幅の予算テストも通る

## 4. 受け入れ基準(EARS 記法)

- WHEN ファイルツリーを作成する(起動・新しいタブ) THE SYSTEM SHALL 並び順を更新順(mtime 降順)にする
- WHEN 更新順でディレクトリを走査する THE SYSTEM SHALL ディレクトリ群をファイル群より前に置き、各群の中を mtime の降順に並べる
- WHEN 2 つの項目の mtime が同じ THE SYSTEM SHALL 名前の昇順(大小無視)で順序を決める
- WHEN 項目の mtime を取得できない THE SYSTEM SHALL その項目を同じ群の末尾に置く(最古として扱う)
- WHEN ファイルツリーにフォーカスがあり、修飾キーなしで `s` が押された THE SYSTEM SHALL 更新順と名前順を切り替え、展開中の全階層を並べ直す
- WHEN 並び順を切り替える THE SYSTEM SHALL ディレクトリの展開状態と選択中のパスを保つ(先頭へ戻さない)
- WHEN 名前順が選ばれている THE SYSTEM SHALL 従来どおり「ディレクトリ先頭 → 名前昇順(大小無視)」で並べる
- WHEN 自動再スキャンで並びが変わる THE SYSTEM SHALL 選択を同じパスの項目へ移す
- WHEN ファイルツリーを描画する THE SYSTEM SHALL サイドバーの題を更新順なら ` FILES 更新順 `、名前順なら ` FILES 名前順 ` にする
- WHEN ファイルツリーにフォーカスがある THE SYSTEM SHALL キーヒントに `s 並替` を出し、ヒント全体を 75 桁以内に収める
- WHEN OSC 7 でフォーカス中ペインの cwd が変わり、ツリーが作り直される THE SYSTEM SHALL そのタブの並び順を引き継ぐ
- WHEN Ctrl+S または Alt+S が押された THE SYSTEM SHALL 並び順を切り替えない(Alt+S は従来どおりステータスバーの表示切替)

## 5. 制約(条件5)

- 技術制約: Rust stable・ratatui・crossterm。新しい crate は足さない。rustfmt は使わず、周辺のコードに手で合わせる(CLAUDE.md)
- 表示: 題とヒントに East Asian Ambiguous 幅の文字(矢印 U+2193 など)を使わない
- 法令/規程: 個人情報を扱わない(ファイル名と mtime の表示だけ)。該当なし
- 期限: なし

## 6. スコープ外

- 並び順を config.toml で指定すること、再起動をまたいで覚えること
- 更新順・名前順以外の並び(サイズ・拡張子・昇順の mtime)
- 1 ディレクトリ 500 件の上限(`MAX_ENTRIES_PER_DIR`)の見直し
- 深い階層の更新を親ディレクトリの順位に反映すること
- ツリー上に日時を表示すること

## 7. 未知の未知の決定事項(Phase 2 の承認結果)

- 500 件の上限 → 現状維持。read_dir の順に 500 件で打ち切ってから並べ替えるので、更新順でも最新のファイルが漏れることがある。既知の限界として記録する
- mtime を取得できない項目 → 最古として扱い、群の末尾に置く
- 同じ mtime → 名前の昇順(大小無視)で決める
- `s` で切り替えたとき → 展開状態と選択パスを保つ(`.` の隠しファイル切替のように先頭へ戻さない)
- ディレクトリの mtime → 直下の追加・削除・改名でしか変わらず、深い階層の編集は反映されない。仕様として許容する
- メタデータの取得 → symlink の判定と mtime を `DirEntry::metadata()` 1 回で取る(Windows では追加の syscall が無く、symlink を辿らない)
- Windows の mtime(Phase 4 で追加・既知の限界) → 列挙で得る最終書き込み時刻は、書き込み用のハンドルがすべて閉じるまで更新されない。開いたまま追記されるログなどは、閉じるまで先頭へ移らない
- 再スキャン直後のクリック(Phase 4 で追加・許容) → 2 秒ごとの再スキャンで行が入れ替わった直後にクリックすると、狙ったのと隣の項目を開くことがある。プレビューと展開は非破壊なので補正しない
- 狭いサイドバー(Phase 4 で追加・許容) → 幅が 16 桁未満だと題 ` FILES 更新順 ` が切れる。短い表記への切り替えはしない
